# Tabloul de control al proprietarului

## Unde vezi progresul

| Întrebare | Unde verifici |
| --- | --- |
| Ce avem de făcut? | Issues deschise |
| La ce se lucrează? | Draft Pull Requests și actualizările din Issues |
| Ce este gata pentru verificare? | Pull Requests pregătite pentru review |
| Ce s-a livrat? | Pull Requests integrate și sarcini acceptate |
| Pot încerca aplicația? | Linkul mediului de test, după configurarea lui |

GitHub arată numai lucrul trimis pe platformă. Numărul de commits nu măsoară calitatea sau orele lucrate.

## Când accepți o livrare

1. Deschide sarcina și citește criteriile de acceptare.
2. Urmează pașii de verificare din Pull Request; cere demonstrație dacă rezultatul nu este clar.
3. Verifică rezultatele testelor și limitările declarate.
4. Cere corecturi sau aprobă rezultatul verificat. Review-ul tehnic și acceptarea funcțională se completează reciproc.

## Configurări administrative rămase

- Invitarea lui Cristian cu Write, după primirea username-ului.
- Confirmarea abonamentului și a celor două locuri; nu presupunem că este GitHub Team sau Copilot.
- Decizia privind trecerea la privat și verificarea protecțiilor disponibile pe planul activ.
- După apariția testelor automate stabile: selectarea lor ca verificări obligatorii în regula main.
- După alegerea găzduirii: configurarea accesului și a secretelor pentru mediul de test.

Acestea sunt lucrări rămase, nu configurări deja activate. Un GitHub Project cu coloane poate fi adăugat ulterior; în prezent folosim Issues și Pull Requests.
